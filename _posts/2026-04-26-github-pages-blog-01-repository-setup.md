# GitHub Pages 블로그 만들기 1: 저장소 생성과 기본 설계

정적 블로그를 시작하려고 할 때 가장 먼저 고민하게 되는 건 어디에 올릴지입니다.
이번에는 GitHub Pages를 이용해서 블로그를 만드는 과정을 정리해 보려고 합니다.

이 시리즈는 아래 순서로 진행합니다.

1. 저장소 생성과 기본 설계
2. Jekyll과 테마 연결
3. GitHub Actions로 배포
4. 배포 오류 해결과 운영 시작

첫 번째 글에서는 GitHub에 저장소를 만들고, 블로그를 어떤 구조로 운영할지 먼저 정리합니다.

## 왜 GitHub Pages로 블로그를 만들까

GitHub Pages는 GitHub 저장소를 기반으로 정적 사이트를 배포할 수 있게 해주는 서비스입니다.

개인적으로는 아래 장점 때문에 시작하기 좋다고 느꼈습니다.

- Git으로 버전 관리가 된다.
- Markdown 기반으로 글을 관리할 수 있다.
- 별도 서버를 직접 운영하지 않아도 된다.
- GitHub Actions와 연결하면 배포 자동화가 쉽다.

특히 개발 기록이나 학습 정리를 남길 목적이라면, 코드와 글을 같은 흐름으로 관리할 수 있다는 점이 큽니다.

## 사용자 사이트와 프로젝트 사이트 차이

GitHub Pages는 크게 두 가지 방식으로 운영할 수 있습니다.

### 1. 사용자 사이트

저장소 이름이 `username.github.io` 형식인 경우입니다.

- 주소 예시: `https://username.github.io/`
- 보통 대표 블로그나 개인 홈페이지 용도로 사용합니다.

### 2. 프로젝트 사이트

일반 저장소를 이용하는 경우입니다.

- 주소 예시: `https://username.github.io/repository-name/`
- 특정 프로젝트 문서나 실험용 블로그에 적합합니다.

이번 블로그는 일반 저장소를 사용했기 때문에 프로젝트 사이트 방식으로 운영됩니다.

## 저장소 만들기

GitHub에서 새 저장소를 생성합니다.

제가 진행한 흐름은 아래와 같습니다.

1. GitHub 우측 상단의 `New repository`를 선택합니다.
2. 저장소 이름을 정합니다.
3. Public 저장소로 생성합니다.
4. 일단 빈 저장소로 시작합니다.

빈 저장소로 시작하면 이후 Jekyll, 테마, 배포 워크플로를 직접 얹는 과정이 더 잘 보입니다.

## 저장소 이름을 정할 때 생각한 점

저장소 이름은 나중에 사이트 주소에 그대로 반영됩니다.

예를 들어 저장소 이름이 `tech-notes`라면 프로젝트 사이트 주소는 아래처럼 됩니다.

```text
https://username.github.io/tech-notes/
```

그래서 저장소 이름은 너무 길지 않고, URL로 쓰기 무난한 형태가 좋습니다.

## 블로그 운영 구조를 먼저 정하기

저장소를 만든 뒤 바로 테마를 붙이기 전에, 어떤 식으로 운영할지 먼저 정리했습니다.

이번 블로그는 아래처럼 가져가려고 했습니다.

- 글은 Markdown 파일로 관리
- GitHub Pages로 배포
- Jekyll 기반 정적 사이트 사용
- 문서형 테마를 적용해서 구조적으로 정리

즉, 단순히 글을 쌓기보다 정리형 아카이브에 가깝게 운영하는 방향입니다.

## 왜 Jekyll 테마를 붙이려고 했나

GitHub Pages는 Jekyll과 궁합이 좋습니다.

특히 문서형 테마를 사용하면 다음과 같은 장점이 있습니다.

- 메뉴 구성이 쉽다.
- 검색 기능을 붙이기 좋다.
- 글과 페이지를 나눠 관리하기 좋다.
- 추후 카테고리 문서나 정리 페이지를 만들기 편하다.

그래서 이번에는 `just-the-docs` 테마를 사용하기로 정했습니다.

## 이번 단계에서 한 일 정리

첫 번째 단계에서 실제로 한 일은 단순합니다.

1. GitHub에 새 저장소 생성
2. 프로젝트 사이트 방식으로 운영하기로 결정
3. Jekyll 기반 블로그로 갈 방향 확정
4. `just-the-docs` 테마 적용을 다음 단계 목표로 설정

설치나 배포보다 먼저 운영 방향을 정해 두면 이후 설정이 훨씬 덜 흔들립니다.
